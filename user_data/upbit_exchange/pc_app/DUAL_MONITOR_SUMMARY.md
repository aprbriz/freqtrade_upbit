## 🔧 기술 아키텍처

### 프로세스 구조
```
단일 Python 프로세스
├─ MainEngine (공유 데이터)
│   ├─ DB Reader
│   ├─ WS Manager (3개 심볼 구독)
│   ├─ BURST Detector (심볼별)
│   ├─ Overlay Manager (심볼별)
│   └─ State Machine (심볼별)
│
├─ Window1 (XRP + BTC)
└─ Window2 (ETH + 진단)
```

### 창 간 동기화
- **공유 메모리**: MainEngine의 스냅샷
- **통신**: PyQt Signals 또는 threading.Event
- **갱신**: 20~60Hz (UI 렌더링 주기)
- **격리**: context_id, generation_id 기반

---

## 📋 통합 진단 패널 (모니터 2 우측)

### 표시 항목 (3개 심볼 전체)
1. **현재 컨텍스트**: 심볼별 MODE/WS/BURST
2. **시간 정보**: Now, last_tick_ts, last_message_age (심볼별)
3. **오버레이 정보**: cutover_ts, 범위, DB catch-up
4. **데이터 정합성**: invalid_trades, ooo_corrected/dropped (심볼별)
5. **WS 연결**: connected_since, 에러, reconnect_attempts (심볼별)
6. **재연결/쿨다운**: 타이머, 상태 이유
7. **BURST 지표**: tick_rate, notional_rate, gate 상태 (심볼별)
8. **최근 갭**: 3개 이벤트

### 행동 버튼
1. `LIVE 시작/유지` (심볼 선택 가능)
2. `DB로 전환(안정)` (심볼 선택 가능)
3. `BURST 알림 ACK` (전체)
